# VØID · работа с исходниками (этап 8)

С этапа 8 игра хранится как модульные исходники в `src/`, а не как один HTML-файл на 14 МБ. Итоговый HTML **генерируется** командой `build8 build` и вручную не правится.

Текущее дерево собирается побайтно в **1.5.35 α**, SHA-256 `b936a549366321b63b8f0c6ac5a8c34013150cffac9ea584b71d3c09c7f4c034`.

## 2. Как это работает

- **Сборка — склейка байтов.** Части берутся в порядке `build/manifest.json`, ничего не преобразуется. Поэтому при неизменных `src/` и манифесте результат побайтно тот же.
- **Игра — один классический скрипт** в одном HTML: без модулей, без бандлера, без новых зависимостей во время игры.
- **Имя и каталог файла на порядок не влияют.** Порядок задаёт только манифест.

**Важно:** код игры — это 229 исторических слоёв обёрток (`index/CHAINS.md`). Порядок их установки — часть поведения. Не переставляйте куски в манифесте и не переносите функции между файлами. Физический перенос (фаза B2) в этапе 8 запрещён.

## 3. Команды

Все команды запускаются из корня (рядом с `src/`). Нужны Python ≥ 3.10 и Node ≥ 18. Для браузерных проверок — Playwright с Chromium.

| Команда | Что делает |
|---|---|
| `python3 tools8/build8.py build` | Собрать `dist/void.html` (~0,1 с) |
| `python3 tools8/build8.py build --without cine` | Вариант без группы: `cine`, `bg` или `cine,bg` (`--out ФАЙЛ`) |
| `python3 tools8/build8.py check` | Все проверки дерева; `--quick` — без индексов; `--json ФАЙЛ` |
| `python3 tools8/build8.py lock --reason "…"` | Зафиксировать изменения (lock, CHANGES.jsonl, dist). **Отказывает**, если проверки красные |
| `python3 tools8/build8.py index` | Перестроить `index/` (~1 мин) |
| `python3 tools8/build8.py where ИМЯ` | Где объявлено имя; где используется (загрузка / из функций / запись); все слои обёрток по порядку |
| `python3 tools8/build8.py blame СТРОКА [--script]` | Какой файл `src/` и строка дали строку собранного HTML (или строку скрипта из стека ошибки) |
| `python3 tools8/build8.py verify-html ФАЙЛ` | Сравнить чужой HTML со сборкой и назвать отличающиеся части |
| `python3 tools8/build8.py selftest` | Самопроверка: 42 случая порчи на копиях, каждый обязан быть пойман |
| `python3 tools8/build8.py regroup --undo` | Отменить раскладку B1 (вернуть 18 фрагментов фазы A) |
| `python3 tools8/variants8.py [--k]` | Четыре варианта сборки в браузере (+ K-стенд без bg) |
| `python3 tools8/navcheck8.py` | Проверка `where`/`blame` по реальным строкам |
| `python3 tools8/offline8.py` | Автономность: file://, HTTP, без сети, телефон |
| `python3 tools8/rollback8.py` | Обратимость: B1 → A → монолит → 1.5.24 → 1.5.35 |
| `python3 tools8/accept8.py` | Полная приёмка (нужен тестовый комплект 1.5.35, `--testkit ПАПКА`) |
| `python3 tools8/snap8.py save\|verify\|restore ИМЯ` | Снимки дерева |
| `python3 tools8/demo8.py` | Демонстрация трёх задач разработчика на копии |

Коды выхода: 0 — успех; 1 — FAIL (проверка выявила отклонение); 2 — ERROR (проверка не выполнена достоверно); 3 — ошибка вызова.

**Статусы:**
- **PASS** — проверка выполнена и прошла.
- **FAIL** — проверка выявила отклонение.
- **ERROR** — проверка не выполнена достоверно.
- **KNOWN** — отклонение точно совпало с реестром известных дефектов. KNOWN — это не PASS.

## 4. Изменить подсистему — 8 шагов

Пример целиком, с реальным выводом команд: `results/demo8.md`, задача 1.

1. **Найти код.** Каталог `src/js/<подсистема>/`, `index/SUBSYSTEMS.md`, `build8 where <имя>`. По строке из ошибки или профилировщика: `build8 blame <строка>` (строка HTML) или `build8 blame <n> --script` (строка скрипта).
2. **Понять, что подсистема использует.** `index/DEPS.md` — ссылки на имена других подсистем: при загрузке (порядок важен) и во время игры.
3. **Найти её состояние.** `index/STATE.md` — какие подсистемы пишут в какое поле `G`. Владельцы — `tools8/audit/ownership6.json`: `G.state` пишет только `scr6`, `G.save` — только `saveSet6`/`saveWith6`, прокачку забега — только `run*6`.
4. **Проверить слои обёрток.** `where` показывает все слои по порядку установки, `index/CHAINS.md` — полный список. Ваш слой будет внешним по отношению к более ранним.
5. **Внести изменение.** Правка файла куска. Новый код — новый кусок (раздел 5).
6. **Собрать.** `build8 build`.
7. **Профильные проверки.** `index/TESTS.md`: подсистема → шаги приёмки, например `accept8 --steps k,e24,trace` (частичный прогон для выпуска не засчитывается).
8. **Убедиться, что остальное цело.** `build8 check`: покрытие, порядок, стражи, синтаксис, аудит инициализации, висячие ссылки. Затем `build8 lock --reason "что и зачем"`, `build8 index`. Перед выпуском — полная `accept8`.

После изменения игры SHA перестаёт быть равным 1.5.35. Это нормально: новая версия фиксируется через `lock`, а `check` с этого момента сверяется с новым lock.

## 5. Куда ставить новый код

- **Новые куски** — в зону «после 1.5.35»: в манифесте после BG и перед `js/boot/…`. Тогда:
  - все таблицы и лексические имена уже созданы;
  - новый слой обёртки оказывается внешним ко всем историческим;
  - CINE и BG остаются непрерывными.
- **Каталог** — по подсистеме. **Номер** — между соседями, например `1235` между `1230` и `1240`.
- **Вставка в середину исторической последовательности** — только с обоснованием в журнале и с чистым аудитом инициализации (`check` → init).
- **Имена из `opt/cine` и `opt/bg`** можно трогать только через `typeof … === 'function'`. Иначе сборка без группы сломается: пункт dangle в `check`.
- **Новый враг или босс** получает свои данные (новая запись в существующей таблице, например `EDEF.<тип>={…}`) и свои функции в своём файле в `enemies/` или `bosses/`. Похожие способности **не объединяются** в общий обработчик.
- **Сохранения:** новые поля — только через миграцию в `saves/`. 17 ключей `localStorage` сторожит `check`, новый ключ — только с записью в `invariants.json` и обоснованием.

## 6. Откат

- **Последняя правка:** вернуть файл (или `snap8 restore <снимок>`), затем `build8 lock --reason "откат …"`.
- **B1 → фаза A:** `build8 regroup --undo`.
- **Дерево → 1.5.35:** `snap8 restore P8.6` (или `P8.4` для фазы A). Сборка даёт b936a549….
- **1.5.35 → 1.5.24:** замороженный конвейер `archive/`; рабочий способ показывает `tools8/rollback8.py` (п. 3).

## 7. Известные дефекты

**cut.cine.live:** сборка без группы cine падает в живом цикле. Полная сборка и сборка без bg работают. Описание и исправление — `docs/FOLLOWUP_cut_cine_live.md`. Остальное — в `docs/REMAINING_ISSUES.md`.
